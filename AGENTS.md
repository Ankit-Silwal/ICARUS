# Repository Guidelines

## Project Structure & Module Organization

This is an npm/Turborepo monorepo. Application code lives in `apps/*`:

- `apps/admin`: Next.js admin application using the App Router under `app/`.
- `apps/teacher`: Next.js teacher application using the App Router under `app/`.
- `apps/student`: Next.js student application using the App Router under `app/`.

Shared workspace packages live in `packages/*`:

- `packages/ui`: shared React components exported from `src/*.tsx`.
- `packages/eslint-config`: shared ESLint presets.
- `packages/typescript-config`: shared TypeScript configuration.

Static app assets belong in each app's `public/` directory. Build output, caches, and dependencies such as `.next/`, `.turbo/`, `dist/`, and `node_modules/` are ignored.

## Build, Test, and Development Commands

Run commands from the repository root unless you are intentionally working inside one package.

- `npm install`: install workspace dependencies. Use Node `>=24` and npm `11.6.1`.
- `npm run dev`: start all persistent development tasks through Turbo.
- `npm run build`: build all apps and packages in dependency order.
- `npm run lint`: run workspace lint tasks.
- `npm run check-types`: run TypeScript checks where configured.
- `npm run format`: format `ts`, `tsx`, and `md` files with Prettier.

Use Turbo filters for focused work, for example `npm exec turbo dev --filter=admin` or `npm exec turbo lint --filter=@repo/ui`.

## Coding Style & Naming Conventions

Write TypeScript and React components with explicit props interfaces where helpful. Use PascalCase for components, camelCase for variables/functions, and lowercase route segment folders in Next apps. Keep shared components in `packages/ui/src` and export them through the package export pattern.

Formatting is handled by Prettier. ESLint is configured per package and shared through `@repo/eslint-config`; fix warnings before opening a PR when practical.

## Testing Guidelines

No test runner is currently configured. For now, rely on `npm run lint`, `npm run check-types`, and targeted manual verification in the relevant app. When adding tests, colocate them near the code under test or add a package-level test directory, and document the new command in `package.json`.

## Commit & Pull Request Guidelines

This repository has no existing commit history, so use concise, imperative commit messages such as `Add shared card component` or `Fix admin layout spacing`. Keep changes scoped to one concern.

Pull requests should include a short summary, validation steps run, linked issues when applicable, and screenshots or recordings for visible UI changes.

## Agent-Specific Instructions

Each Next app contains an app-level `AGENTS.md` generated by Next.js. Read that file, then consult local Next documentation in the app's `node_modules/next/dist/docs/` before changing Next-specific APIs or conventions.

## Service Architecture and Ports

Backend services live under `services/*`. Keep HTTP composition in `app.ts`, process startup in `index.ts`, route declarations in `routes/`, request handling in `controllers/`, business logic in `services/`, and shared service-local declarations in `types/`. Do not put business logic in the API gateway.

- API Gateway: `4000` (the only public backend port)
- Identity Service: `8000` (internal; public prefix `/api/v1/auth`)
- Classroom Service: `4002`
- Assessment Service: `4003`
- Execution Service: `4004`
- Integrity Service: `4005`

The gateway removes `/api/v1/auth` before forwarding identity requests. Current public identity routes are:

- `GET /api/v1/auth/oauth/google`
- `GET /api/v1/auth/oauth/google/callback`
- `GET /api/v1/auth/session`
- `POST /api/v1/auth/logout`
- `GET /api/v1/auth/users/me`
- `GET /api/v1/auth/admin/users`
- `GET /api/v1/auth/admin/users/:id`
- `PATCH /api/v1/auth/admin/users/:id/status`
- `PATCH /api/v1/auth/admin/users/:id/role`
- `GET|POST /api/v1/auth/admin/teachers/invitations`
- `POST /api/v1/auth/admin/teachers/import`
- `GET /api/v1/auth/admin/teacher-imports/:id`
- `GET /api/v1/auth/admin/audit-logs`

Identity uses Google OAuth only. Secrets and college-specific values belong in `.env`, never source control. Prisma schema changes require a migration under `services/identity/prisma/migrations`; do not create or alter identity tables from application startup code.
